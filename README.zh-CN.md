# Warframe 极化规划器

[立即使用：https://forma.him.xx.kg/](https://forma.him.xx.kg/)

[Back to English README](README.md)

一个用于计算 Warframe 极化方案的静态网页工具。它可以根据多套配卡、MOD 容量、极性、元素顺序、劣化槽和已有极性，推导尽可能省 Forma 的最终槽位布局。

简单说，它解决的是这个问题：

> 我应该把武器最终极化成什么样，才能让这些配卡尽量共存，并且少用 Forma？

项目支持中英文 MOD 数据库、自动匹配、自定义 MOD、多配置共同最优解、元素 MOD 顺序约束、劣化槽、全能福马、Umbra 福马，以及容量不足时的最优方案提示。

## 功能特点

- 支持英文 / 简体中文界面。
- 根据浏览器语言自动选择默认语言：中文浏览器默认中文，其它语言默认英文。
- 中文和英文 MOD 数据库互相独立。
- 支持 MOD 名称自动补全，输入部分名称即可匹配。
- 支持自定义 MOD，避免数据库缺失时无法使用。
- 仿游戏内布局：8 个普通槽为两行四列，右侧单独 1 个劣化槽。
- 支持多套配置共同计算最终极化方案。
- 每套配置单独填写总容量。
- 支持元素 MOD 顺序不变。
- 支持劣化槽 MOD，也可以选择不安装。
- 支持保护已有极性，避免破坏旧极化。
- 支持全能福马和 Umbra 福马策略。
- 支持浏览器端截图识别：第 1 页导入已有槽位，第 2 页导入目标配卡并计算。
- 即使容量不足，也会展示当前最优站位，并提示还差多少容量。
- 纯静态网页，无后端、无构建步骤、无需账号。

## 使用方法

### 1. 设置当前槽位极性

第一步用于设置当前武器已有的极性。

槽位布局对应游戏内配卡界面：

```text
1 2 3 4   劣化槽
5 6 7 8
```

主要选项：

- `允许覆盖已有极性`：开启后，算法可以替换已有极性，以换取更少 Forma。
- 关闭后，已有的非空极性会被保护，算法会尽量只新增极化，不破坏旧极性。
- `优先使用全能福马`：默认关闭。开启后，多配置情况下如果全能福马能节省超过 1 个普通 Forma，才会优先使用。
- `优先使用 Umbra 福马`：默认关闭。开启后，如果配卡含 Umbra MOD，会在 Forma 次数相同的候选中优先匹配 Umbra 槽；其它情况仍需 Umbra 福马节省超过 1 个普通 Forma 才会优先使用。

第 1 页也可以上传自己的配卡截图来导入已有槽位。工具会根据 MOD 消耗数字颜色推断已匹配的槽位极性；无法可靠判断的空槽或错配槽会保留原来的手动设置。

如果没有其它可行方案，工具仍然会在必要时使用全能福马或 Umbra 福马。

### 2. 填写目标配卡

可以手动填写，也可以在第 2 页上传目标配卡截图。截图识别会按画面中的 MOD 顺序写入普通槽，自动识别右侧或顶部右侧的劣化槽；如果是战甲截图，还会尝试读取顶部左侧光环槽的容量加成并更新总容量。

截图识别完全在浏览器端运行，适合 GitHub Pages 静态部署。不同分辨率截图会按相对位置识别，但仍建议保留完整 MOD 卡片、消耗数字和核心槽位区域。

每套配置包含：

- 总容量。
- 8 个普通槽 MOD。
- 1 个可选劣化槽 MOD。

`总容量` 指的是武器容量加上光环 MOD / 架势 MOD 后，游戏内最终可用的总容量。

例如：

- 武器本身 60 容量，没有额外加成，就填写 `60`。
- 近战武器受到架势 MOD 加成后，应填写游戏内显示的最终总容量。

MOD 名称支持自动匹配。输入部分名称后，从候选项里选择即可。

如果数据库里没有需要的 MOD，可以选择自定义，或者手动填写：

- MOD 名称。
- 点数消耗。
- 极性。

MOD 名称留空时，表示该槽不安装 MOD。

输入完成后按 `Tab`，可以快速移动到下一个 MOD 位置。

### 3. 勾选元素 MOD

如果某张 MOD 参与元素组合顺序，请勾选 `元素`。

算法会保证所有勾选元素的 MOD，在最终普通槽站位中的相对顺序不变。

普通槽顺序与游戏一致：

```text
1 2 3 4
5 6 7 8
```

例如原始元素顺序是：

```text
冰 -> 毒 -> 火
```

最终站位也会保证冰在毒之前，毒在火之前。

### 4. 新增多套配置

点击 `新增配置` 可以录入多套配卡。

算法会计算一套共同的最终极化布局，让所有配置尽量共存。

如果即使最优极化后容量仍然不够，工具不会直接停止，而是会展示当前最优站位，并提示容量差额。

### 5. 查看结果

结果页会展示：

- 最少需要多少次 Forma。
- Forma 作业单。
- 最终极化槽位。
- 每套配置的 MOD 站位。
- 每张 MOD 极化后的实际消耗。
- 如果极化改变容量，会同时显示原始容量和极化后容量。
- 如果容量不足，会显示还差多少容量。

## 极化容量规则

同极性时，MOD 容量减半并向上取整：

```text
9 / 2 = 4.5 -> 5
```

异极性时，容量增加 25%，并向上取整：

```text
9 + ceil(9 * 0.25) = 12
```

无极性槽位或无极性 MOD，容量不变。

全能极性可以匹配非 Umbra 极性。Umbra MOD 仍然需要 Umbra 极性才能享受减半。

## MOD 数据库说明

项目包含本地 MOD 数据：

```text
mods.en.js
mods.en.json
mods.zh-hans.js
mods.zh-hans.json
```

JSON 文件是更容易查看和校验的数据快照。

JS 文件是浏览器直接使用的版本，会把数据挂载到全局变量：

```js
window.WF_MOD_DATABASE
window.WF_MOD_DATABASE_EN
```

这样项目不需要构建工具，也能直接作为静态网页运行。

数据主要来自 WarframeStat / Warframe 导出数据。上游数据里可能存在同名 MOD、隐藏变体或特殊版本，所以项目会额外做去重和优先级处理，尽量选择玩家实际使用的普通版本。

开发中重点校验过的例子：

```text
压迫点 -> 普通版，9 点
压迫点 Prime -> Prime 版，14 点
病原弹头 -> 普通版，11 点
戏法增幅 -> 普通版，7 点
```

## 语言逻辑

页面会根据浏览器语言选择默认界面：

- 浏览器语言以 `zh` 开头：默认简体中文界面和中文 MOD 数据库。
- 其它语言：默认英文界面和英文 MOD 数据库。

用户也可以在页面右上角手动切换语言。

中文模式只搜索中文 MOD 名称，英文模式只搜索英文 MOD 名称，两套数据库不会混用。

## 开发说明

项目没有构建步骤，修改文件后刷新浏览器即可。

可以用下面的命令检查 JavaScript 语法：

```bash
node --check app.js
```

由于 MOD 数据来自外部游戏数据导出，上游可能存在错误或重复。如果某张 MOD 的容量或版本不正确，请优先检查本地 JSON 数据，并根据情况调整去重规则或数据源。
